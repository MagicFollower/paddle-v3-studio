# 项目与模型存放位置规范

本规范约定 `方案B：版面分析与OCR` 下各工程与模型库的存放位置、相对路径推导方式，
以及可移植性规则。目标：**整套目录拷到任意机器/任意盘符，保持相对结构即可运行，
代码中不出现任何硬编码绝对路径。**

## 1. 目录布局

```
OCR-ALONE/                              ← 工作区根（ASCII）
├─ MODEL/                               ← 方案A 的 GGUF 离线包（paddleocr-vl-studio 用）
├─ MODEL-V3/                            ← 方案B 的 Paddle 模型库（ASCII，约 916 MB）
│  └─ official_models/                  ← 10 个模型目录，见「离线模型使用清单」
├─ paddleocr-vl-studio/                 ← 方案A 工程
└─ 方案B：版面分析与OCR/                 ← 本 git 仓库根（路径含中文）
   ├─ .gitignore
   ├─ paddle-v3-studio/                 ← V3 流水线工程
   │  ├─ server/  src/  scripts/  doc/
   │  ├─ fixtures/                      ← 样例合同与真图（入库）
   │  ├─ data/                          ← 运行时写盘区（忽略，不入库）
   │  ├─ .venv/  node_modules/  dist/   ← 依赖与构建产物（忽略）
   │  └─ run.cmd / build.cmd
   └─ contract-source/                  ← Spring Boot 数据源工程
      ├─ src/  pom.xml
      ├─ data/                          ← H2 文件库（忽略）
      └─ target/                        ← Maven 产物（忽略）
```

**关键约束**：`MODEL-V3` 与 `方案B：版面分析与OCR` 是**同级兄弟目录**，都在 ASCII 的
`OCR-ALONE` 根下。工程相对模型库的位置恒为 `../../MODEL-V3`。

## 2. 为什么模型库必须在 ASCII 路径

Paddle 的 C++ 推理引擎在 Windows 上**读不了含中文的路径**：同一份模型，ASCII 路径
加载成功，中文路径报 `json.exception.parse_error.101 empty input`（本机 A/B 实测）。

本工程在「方案B：版面分析与OCR」下，路径含中文，所以**模型库不能放工程内**，必须放
ASCII 的 `OCR-ALONE/MODEL-V3`。这与方案A 工程引用 `../MODEL/offline` 的惯例一致。

> 工程内的 `data/`、`fixtures/` 含中文无碍——它们由 Python/WPS 读写；只有送进 Paddle
> 推理引擎的模型目录受此限制。

## 3. 相对路径推导（代码唯一写法）

所有路径从 `__file__` 推导，**不写死盘符/用户名**：

| 量 | 推导 | 位置 |
|---|---|---|
| 工程根 `ROOT` | `Path(__file__).resolve().parent.parent` | [`server/config.py:7`](../server/config.py) |
| 运行时区 `DATA` | `ROOT / "data"` | [`server/config.py:8`](../server/config.py) |
| 模型库 `MODELS_HOME` | `ROOT.parent.parent / "MODEL-V3"` | [`server/config.py:15-16`](../server/config.py) |
| 模型目录 | `MODELS_HOME / "official_models" / <name>` | [`server/pipeline.py`](../server/pipeline.py) `model_dir()` |
| 数据源 jar | `ROOT.parent / "contract-source/target/contract-source.jar"` | [`scripts/check_studio.py`](../scripts/check_studio.py) |

- `.resolve()` 只是把**相对推导结果**规范化为绝对路径供运行时使用，源头仍是
  `__file__` 相对位置——这不是硬编码绝对路径，目录整体搬迁后自动跟随。
- WPS COM 的 `Documents.Open` 要求绝对路径，故 [`server/contract.py:32`](../server/contract.py)
  用 `docx_path.resolve()` 现算，同样源自相对路径。
- `.cmd` 脚本一律 `cd /d "%~dp0"`（脚本自身目录）后再用相对路径；H2 用
  `jdbc:h2:file:./data/contractdb`（相对工作目录）。

### 模型库位置可覆盖

默认 `../../MODEL-V3`；若模型库放别处，设环境变量即可，**无需改代码**：

```bat
set PADDLE_V3_MODEL_HOME=D:\paddle-models\MODEL-V3
run.cmd
```

该目录仍须是 **ASCII 路径**（见第 2 节）。

## 4. 路径审计结论

对两工程源码（`*.py *.js *.vue *.cmd *.yml *.xml *.sql *.java`）排查硬编码绝对路径
（盘符 `X:\`/`X:/`、`/Users/`、`/home/`、`%USERPROFILE%`、字面 `Users/Desktop/OCR-ALONE`）：

**未发现硬编码绝对文件路径。** 命中项均为：`http://127.0.0.1` 服务地址、XML 命名空间、
pip/npm 仓库 URL、以及注释里对相对布局的描述。可用校验脚本复跑：

```bat
.venv\Scripts\python.exe scripts\check_paths.py
```

## 5. 可移植性规则（Dos / Don'ts）

**Do**
- 新增路径一律从 `ROOT`（`__file__` 推导）或 `%~dp0` 出发拼接相对段。
- 模型库、依赖、构建产物、运行时数据保持被 `.gitignore` 忽略，靠脚本复现。
- 搬迁时整体保持第 1 节的相对结构（尤其 `MODEL-V3` 与仓库根同级）。

**Don't**
- 不写 `C:\Users\...`、`D:\...` 等字面绝对路径进代码或脚本。
- 不把模型库放进含中文的工程目录（Paddle 引擎会加载失败）。
- 不把 `.venv/`、`node_modules/`、`MODEL-V3/`、`data/` 提交入库。

## 6. 新机器部署

```bat
:: 1) 保持目录结构克隆/拷贝（MODEL-V3 与仓库根同级）
:: 2) 装依赖 + 预下载模型（仅此处联网）
cd 方案B：版面分析与OCR\paddle-v3-studio
scripts\setup.cmd
:: 3) 构建前端 + 起服务
build.cmd
run.cmd
:: 4) 另起合同数据源
..\contract-source\run.cmd
```

若已有 `MODEL-V3` 离线包，直接拷到同级位置即可跳过模型下载（setup 仍会校验就位）。
