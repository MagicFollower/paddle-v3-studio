# 离线模型使用清单

本清单台账化 `paddle-v3-studio` 所用的全部 Paddle 推理模型。模型库统一存放于
**`../../MODEL-V3/official_models/`**（相对本工程根目录），共 **10 个模型目录、约 916 MB**。
安装阶段由 `scripts/setup_models.py` 一次性预下载，**运行时零联网**。

> 模型库为什么不在工程内、为什么必须 ASCII 路径，见
> [项目与模型存放位置规范](./项目与模型存放位置规范.md)。

## 1. 模型台账

| 模型目录 | 体积 | 角色 | 流水线阶段 | 配置键 |
|---|---|---|---|---|
| `PP-DocLayoutV3` | 126 MB | 版面检测（23 类区域：doc_title/text/table/figure…） | 版面分析 | `model.layout_model` |
| `PP-OCRv5_server_det` | 85 MB | 文本检测（定位文本行四点框） | OCR | `model.det_model` |
| `PP-OCRv5_server_rec` | 81 MB | 文本识别（行图像→文字+置信度） | OCR | `model.rec_model` |
| `SLANeXt_wired` | 349 MB | 有线表格结构识别（→HTML） | 表格识别 | `model.table_model` |
| `SLANet_plus` | 8 MB | 无线表格结构识别（→HTML） | 表格识别 | 自动解析 |
| `PP-LCNet_x1_0_table_cls` | 7 MB | 表格分类（有线/无线分流） | 表格识别 | 自动解析 |
| `RT-DETR-L_wired_table_cell_det` | 124 MB | 有线表格单元格检测 | 表格识别 | 自动解析 |
| `RT-DETR-L_wireless_table_cell_det` | 124 MB | 无线表格单元格检测 | 表格识别 | 自动解析 |
| `PP-LCNet_x1_0_doc_ori` | 7 MB | 文档/表格方向分类 | 表格识别子管线 | 自动解析 |
| `PP-LCNet_x1_0_textline_ori` | 7 MB | 文本行方向分类 | 表格 OCR 子管线 | 自动解析 |

- **显式配置 4 个**：`layout_model / det_model / rec_model / table_model`，在
  [`server/config.py:28-31`](../server/config.py) 定义默认值，经
  [`server/pipeline.py`](../server/pipeline.py) 的 `model_dir()` 显式传入流水线。
- **自动解析 6 个**：表格识别子管线（`table_recognition_v2`）内部按默认模型名从
  同一缓存目录加载，无需逐个配置；预下载时一并拉取，运行时同样离线命中。

## 2. 模型目录文件构成

每个模型目录的标准三件套（Paddle 静态图推理格式）：

| 文件 | 作用 |
|---|---|
| `inference.json` | PIR 计算图程序（新格式；Paddle 3.x 优先于 `.pdmodel`） |
| `inference.pdiparams` | 权重参数 |
| `inference.yml` | 预处理/后处理与模型元配置 |

个别模型附带额外文件（不影响加载）：`PP-LCNet_x1_0_doc_ori` 带 `README.md`/`config.json`，
`PP-LCNet_x1_0_textline_ori` 带演示图 `img_textline180_demo_res.*`。

## 3. 版本与来源

| 项 | 值 |
|---|---|
| 流水线 | `PP-StructureV3`（PaddleOCR 3.x V3 方案） |
| paddleocr / paddlex | 3.7.0 / 3.7.2 |
| paddlepaddle | 3.4.0（GPU cu129 优先，CPU 兜底） |
| 下载源 | 百度 BOS 官方源（`PADDLE_PDX_MODEL_SOURCE=bos`）；HuggingFace 默认源在本机会挂起 |
| 许可 | Apache-2.0（PaddlePaddle 官方模型） |

## 4. 离线纪律

1. **安装阶段联网，运行时零联网**：`scripts/setup.cmd` → `setup_models.py` 预下载全部
   10 个模型到 `MODEL-V3/official_models/`，并真跑一次 warm-up 推理验证加载。
2. **本地优先**：PaddleX 命中 `official_models/<name>` 即用盘上文件，不触网
   （`inference/utils/official_models.py` 的 `_get_model_local_path` 先查本地）。
3. **更新检查禁用**：`PADDLE_PDX_DISABLE_UPDATE_CHECK=True`、
   `PADDLE_PDX_DISABLE_MODEL_SOURCE_CHECK=True`（[`server/pipeline.py:15-18`](../server/pipeline.py)）。
4. **缺模型不偷下载**：显式配置的 4 个模型若缺目录，`model_dir()` 直接抛
   `MODEL_MISSING` 并提示跑 setup；不回落假数据。

## 5. 就位校验与复下载

**双击下载（推荐，纯标准库、无需 venv）**：直接双击
[`scripts/download_models.py`](../scripts/download_models.py)，用系统关联的 Python 即可
从 BOS 源下载全部 10 个模型，按 `official_models/<name>/inference.*` 布局存放；
**目录已存在则跳过**，中断后重跑即续传，结尾暂停便于查看结果。

```bat
:: 校验全部模型就位（缺失非零退出，会真跑 warm-up，需 venv）
.venv\Scripts\python.exe scripts\setup_models.py

:: 运行时状态（前端「系统设置」也读这个）
curl http://127.0.0.1:8390/api/model/status

:: 重新下载某个模型：删掉对应目录后双击 download_models.py（或命令行运行）
rmdir /s /q ..\..\MODEL-V3\official_models\SLANeXt_wired
python scripts\download_models.py
```

`/api/model/status` 回包中 `models.*.present` 逐项标记 4 个主模型是否在盘上，
`device` 段标记 GPU/CPU 与降级原因。
